## Workflow / Important Details
- Deploy: `railway up --detach`. Commits: only commit/push when the user explicitly asks.
- Local dev server: `node server.js` on 0.0.0.0:8080. Restart it (kill PID) after editing `server.js` so the change loads; static files under `public/` are read from disk each request (no restart needed).
- Cache busting: after ANY edit to `public/js/app.js`, `public/css/app.css`, `public/app.html`, `public/pinyin-chart.html`, bump the version `v=NN` in `public/app.html` (6 refs since v103: two preloads ~L21-22, stylesheet ~L206, translate.js ~L217, script ~L1855, shop.js ~L214) AND `CACHE = 'mandarincourse-vNN'` in `public/sw.js` (v=NN refs must always match the SW CACHE value). Ranges have gone v43→v143. The `console`-override shim (~L19137 of app.js) makes DevTools attribute every log line to the shim, so real call sites are at the file:line the source shows — don't trust DevTools line numbers. Prod deploy = commit + push to GitHub; Vercel auto-builds `main`. **Prod verification: ALWAYS run `node scripts/prod-verify.cjs`** (v131+) — it reads the expected CACHE from local `public/sw.js`, polls prod `sw.js` until it matches, asserts 6/6 `?v=NN` refs in prod `app.html`, and SHA-256-compares all 6 assets. Compares are LF-normalized because Vercel serves text as LF while the local working copy is CRLF — a raw byte compare ALWAYS false-negatives (/sw.js and /app.html showed as DIFF at v130/v131 despite identical content; don't re-diagnose this).
- ENCODING HAZARD (critical): `public/app.html` is UTF-8 (no BOM) and MUST stay that way. Never write it with PowerShell `Set-Content -Encoding UTF8` (adds a BOM), and NEVER round-trip it through PowerShell `Get-Content`/`Set-Content` at all — `Get-Content` without `-Encoding UTF8` reads a BOM-less UTF-8 file as Windows-1252, so `| Set-Content -Encoding UTF8` silently DOUBLE-ENCODES every non-ASCII char (this recurred during the v53 cache bump and the level-modal emojis turned into `ðŸž‰`-style mojibake again). Use the Edit tool, or .NET `[System.IO.File]::WriteAllText(path, str, (New-Object System.Text.UTF8Encoding($false)))`. If it DOES recur: reverse by encoding each byte as CP1252 (special map: €→0x80, —→0x97, –→0x96, œ→0x9C, ž→0x9E, …, ƒ→0x83, ‰→0x89), i.e. the inverse of the transform used in this file; clean originals are backed up at `C:\Users\HP\AppData\Local\Temp\opencode\app.html.mojibake-backup` and `app.html.mojibake2`.
- Supabase partial setup: user must run `supabase/setup.sql` (now includes the `leads` table) in Supabase dashboard SQL editor (project `enisseoyaledojeuykbd`) for login/progress/activity + lead capture; `SUPABASE_SERVICE_ROLE_KEY` still unset. ## Shop (`/app/shop`, v105) — merch + digital downloads
- Catalog: `shop/products.json` (repo root, committed) — `{merchStoreUrl, products[]}` with `id/type('digital')/name/desc/price/size/image/file/downloadName`. Prices are SERVER-authoritative only: `/api/shop/create-order` + `/api/shop/capture-order` re-read the catalog (client never sends a price; capture also checks the PayPal captured amount equals catalog price). Sell more → add entries here; ship files → `shop/files/<id>.pdf` (placeholder PDFs currently committed so the flow is testable).
- Digital delivery is STATELESS: `POST /api/shop/capture-order` (only after PayPal status COMPLETED) mints `{productId|exp}.HMAC` (base64url, `crypto.createHmac('sha256', SHOP_SIGNING_KEY || PAYPAL_CLIENT_SECRET)`) and returns a `download.url` valid 7 days; `GET /api/shop/download/:slug` verifies the token + expiry + path (must stay under repo `shop/`) and streams the file. No order DB needed — survives Vercel serverless. 403 on invalid/expired, 404 "not ready" if the file is missing.
- **Free-download email gate (v105):** `POST /api/shop/free-download` now requires `{ productId, email, source }`. Email is validated server-side; the handler stores a lead row in Supabase `public.leads` via PostgREST (`{email, product_id, source}` + `?on_conflict=email` for dedupe). If `SUPABASE_SERVICE_ROLE_KEY` is unset, the download still succeeds (`leadStored:false`) but logs an error — fail-open so a Supabase outage never blocks the flow. Lead insert failures are also catch-and-continue. Client: `shop.js` now opens an email modal (`#shopLeadModal`) before minting; on submit it POSTs the email and redirects to the signed `download.url`. `source` defaults to `utm_source || utm_medium || 'direct'` (set by the URL query). Email is cached in `localStorage` key `mc_lead_email` so repeat visits pre-fill the field.
- Merch = print-on-demand: the "Shop Merch" button just opens `merchStoreUrl` in a new tab (Printify's hosted storefront handles checkout/shipping — set it to your Printify store link; empty string renders a "coming soon" card). NO code path on our side ships physical goods.
- Client: `public/js/shop.js` (deferred after paypal.js; added to `urlsToCache`). Loads catalog via `GET /api/shop/products`, renders into `#shopDigitalGrid` + `#shopMerchCard`, reuses `initPayPalSDK` loader + `MANDARINCOURSE_CONFIG.PAYPAL_CLIENT_ID`, renders PayPal Buttons into `#shopPaypalContainer`, success modal `#shopSuccessModal` shows the signed download link. Buttons per-product rendered one at a time (previous closed via `activeButtons.close()`). Free products now use a lead-capture modal (`#shopLeadModal`) before minting.
- Tested locally without a real PayPal sale: `node --check`, catalog fetch, email-gate 400 cases (missing + invalid email), lead insert to mock Supabase (receives the correct PostgREST `on_conflict=email` payload with normalized `fan@example.com`), and signed-download endpoint (valid→200 PDF, tampered/expired→403) all verified; a real sale needs PAYPAL keys (set in `.env`/Railway/Vercel); lead capture needs `SUPABASE_SERVICE_ROLE_KEY` (set in `.env`/Railway/Vercel).

## AI Tutor ("Li Laoshi") — how it's set up (`public/js/app.js`)
Two input paths — a Web Speech API path and a recording-fallback path:

1. **Recording fallback (what actually works on the user's Windows laptop)** — `startAudioRecording(btn, ic)` ~L14907:
   - Captures the RAW `getUserMedia` stream into `MediaRecorder`. IMPORTANT: do NOT route the mic through a Web Audio gain/pitch graph for recording — a suspended/failed AudioContext silently outputs silence on Windows. Analyser is used ONLY for level metering (`window._recLevelIv` interval, 120ms, time-domain peak).
   - Started directly from `tutSpeak()` when `window._useAudioFallback` is set (set permanently after the first SpeechRecognition `no-speech` failure on this machine; cleared only when the user picks a mic via `selectMicDevice`). SpeechRecognition takes ~6-8s to error on this machine, so the fallback flag skips it entirely.
   - **Auto-stop on silence** (added v52, level-aware since v131): the level interval tracks last-sound time (`_recLastSound`); after `liveSilenceMs()` of continuous sub-threshold (peak < 0.025) audio, ≥2s after start (`_recStartedAt`), it auto-stops the recorder by calling `startAudioRecording` again. Flat per-level values (v131, deliberate — no dynamic scaling component; tune from real usage if needed): silence 1700ms never/beginner, 2000ms intermediate, 2400ms advanced; hard cap `liveCapMs()` = 10s (15s advanced). So hands-free turns: AI speaks → auto-listens → user speaks → auto-stops on pause → sends.
   - **Live-mode persistent mic stream (v131 — fix for head-truncated HSK-5 transcripts like "去﹐ 。"/"祭祷")**: in `tutor_mode==='live'` ONE `MediaStream` (`liveMicStream`) stays open across turns — a fresh `getUserMedia` every turn cost ~74ms–1s on this Windows laptop, and the "Recording... speak now" hint used to render BEFORE `getUserMedia` resolved, so the first syllables of each reply were lost to Whisper. Rules: hint only says "speak now" after `mediaRecorder.start()` succeeds; track stops went through `maybeStopActiveMic()` (keeps the live stream, stops anything else); `releaseLiveMicStream()` on mode exit (`saveGeminiSettings` non-live), mic change (`selectMicDevice`), and `beforeunload`. Don't reintroduce unconditional track stops. **v132: the mic BUTTON flip (`updateMicUI('recording')`) also moved to capture-open** (was at tap time — the button is the dominant "safe to speak" signal and flipped 74ms–1s before capture opened; `srOn=true` still happens early as the re-entry guard). So NOTHING visual says "recording" before `mediaRecorder.start()` succeeds: button, wave bars, and hint all flip together. Known cosmetic leftover: the "speak now" text targets `#tutHint`, which sits inside the blackboard pane hidden by `app.css` `.board-panel { display:none !important }` (spatial redesign) — the text write is harmless but invisible; mirroring it to the visible `#tutStatus` is a deferred nice-to-have. Gate: `tests/regression/live-mic-lifecycle-test.cjs` (13 checks incl. zero getUserMedia re-calls across turns, button idle at tap / Stop at capture-open; fake audio device). One-time manual real-mic check: `node tests/scratch/live-capture-e2e.cjs`.
   - `mediaRecorder.onstop` gate: if peak < 0.05 → treated as silent (bytes are NOT a reliable silence check — AAC encodes silence as data too); skips Gemini, offers `autoDetectMic()` sweep (level-based) and auto-switches `mic_device_id`. Real speech → `sendAudioToGemini(base64, 3, mime)`.
   - Note: only the OLD pitch-track visualizer still uses the Web Audio gain graph (in the SpeechRecognition `onstart`), which is fine — it's audio-out only.
