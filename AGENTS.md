## Workflow / Important Details
- Deploy: `railway up --detach`. Commits: only commit/push when the user explicitly asks.
- Local dev server: `node server.js` on 0.0.0.0:8080. Restart it (kill PID) after editing `server.js` so the change loads; static files under `public/` are read from disk each request (no restart needed).
- Cache busting: after ANY edit to `public/js/app.js`, `public/css/app.css`, `public/app.html`, `public/pinyin-chart.html`, bump the version `v=NN` in `public/app.html` (6 refs since v103: two preloads ~L21-22, stylesheet ~L206, translate.js ~L217, script ~L1855, shop.js ~L214) AND `CACHE = 'mandarincourse-vNN'` in `public/sw.js` (v=NN refs must always match the SW CACHE value). Ranges have gone v43→v105. The `console`-override shim (~L19137 of app.js) makes DevTools attribute every log line to the shim, so real call sites are at the file:line the source shows — don't trust DevTools line numbers. Prod deploy = commit + push to GitHub; Vercel auto-builds `main`, then poll `https://mandarincourse.app/sw.js` for the new CACHE value and SHA-256-compare prod `?v=NN` assets vs local.
- ENCODING HAZARD (critical): `public/app.html` is UTF-8 (no BOM) and MUST stay that way. Never write it with PowerShell `Set-Content -Encoding UTF8` (adds a BOM), and NEVER round-trip it through PowerShell `Get-Content`/`Set-Content` at all — `Get-Content` without `-Encoding UTF8` reads a BOM-less UTF-8 file as Windows-1252, so `| Set-Content -Encoding UTF8` silently DOUBLE-ENCODES every non-ASCII char (this recurred during the v53 cache bump and the level-modal emojis turned into `ðŸž‰`-style mojibake again). Use the Edit tool, or .NET `[System.IO.File]::WriteAllText(path, str, (New-Object System.Text.UTF8Encoding($false)))`. If it DOES recur: reverse by encoding each byte as CP1252 (special map: €→0x80, —→0x97, –→0x96, œ→0x9C, ž→0x9E, …, ƒ→0x83, ‰→0x89), i.e. the inverse of the transform used in this file; clean originals are backed up at `C:\Users\HP\AppData\Local\Temp\opencode\app.html.mojibake-backup` and `app.html.mojibake2`.
- Supabase partial setup: user must run `supabase/setup.sql` (now includes the `leads` table) in Supabase dashboard SQL editor (project `enisseoyaledojeuykbd`) for login/progress/activity + lead capture; `SUPABASE_SERVICE_ROLE_KEY` still unset.

## Shop (`/app/shop`, v105) — merch + digital downloads
- Catalog: `shop/products.json` (repo root, committed) — `{merchStoreUrl, products[]}` with `id/type('digital')/name/desc/price/size/image/file/downloadName`. Prices are SERVER-authoritative only: `/api/shop/create-order` + `/api/shop/capture-order` re-read the catalog (client never sends a price; capture also checks the PayPal captured amount equals catalog price). Sell more → add entries here; ship files → `shop/files/<id>.pdf` (placeholder PDFs currently committed so the flow is testable).
- Digital delivery is STATELESS: `POST /api/shop/capture-order` (only after PayPal status COMPLETED) mints `{productId|exp}.HMAC` (base64url, `crypto.createHmac('sha256', SHOP_SIGNING_KEY || PAYPAL_CLIENT_SECRET)`) and returns a `download.url` valid 7 days; `GET /api/shop/download/:slug` verifies the token + expiry + path (must stay under repo `shop/`) and streams the file. No order DB needed — survives Vercel serverless. 403 on invalid/expired, 404 "not ready" if the file is missing.
- **Free-download email gate (v105):** `POST /api/shop/free-download` now requires `{ productId, email, source }`. Email is validated server-side; the handler stores a lead row in Supabase `public.leads` via PostgREST (`{email, product_id, source}` + `?on_conflict=email` for dedupe). If `SUPABASE_SERVICE_ROLE_KEY` is unset, the download still succeeds (`leadStored:false`) but logs an error — fail-open so a Supabase outage never blocks the flow. Lead insert failures are also catch-and-continue. Client: `shop.js` now opens an email modal (`#shopLeadModal`) before minting; on submit it POSTs the email and redirects to the signed `download.url`. `source` defaults to `utm_source || utm_medium || 'direct'` (set by the URL query). Email is cached in `localStorage` key `mc_lead_email` so repeat visits pre-fill the field.
- Merch = print-on-demand: the "Shop Merch" button just opens `merchStoreUrl` in a new tab (Printify's hosted storefront handles checkout/shipping — set it to your Printify store link; empty string renders a "coming soon" card). NO code path on our side ships physical goods.
- Client: `public/js/shop.js` (deferred after paypal.js; added to `urlsToCache`). Loads catalog via `GET /api/shop/products`, renders into `#shopDigitalGrid` + `#shopMerchCard`, reuses `initPayPalSDK` loader + `MANDARINCOURSE_CONFIG.PAYPAL_CLIENT_ID`, renders PayPal Buttons into `#shopPaypalContainer`, success modal `#shopSuccessModal` shows the signed download link. Buttons per-product rendered one at a time (previous closed via `activeButtons.close()`). Free products now use a lead-capture modal (`#shopLeadModal`) before minting.
- Tested locally without a real PayPal sale: `node --check`, catalog fetch, email-gate 400 cases (missing + invalid email), lead insert to mock Supabase (receives the correct PostgREST `on_conflict=email` payload with normalized `fan@example.com`), and signed-download endpoint (valid→200 PDF, tampered/expired→403) all verified; a real sale needs PAYPAL keys (set in `.env`/Railway/Vercel); lead capture needs `SUPABASE_SERVICE_ROLE_KEY` (set in `.env`/Railway/Vercel).

## AI Tutor ("Li Laoshi") — how it's set up (`public/js/app.js`)
Two input paths — a Web Speech API path and a recording-fallback path:

1. **Recording fallback (what actually works on the user's Windows laptop)** — `startAudioRecording(btn, ic)` ~L14907:
   - Captures the RAW `getUserMedia` stream into `MediaRecorder`. IMPORTANT: do NOT route the mic through a Web Audio gain/pitch graph for recording — a suspended/failed AudioContext silently outputs silence on Windows. Analyser is used ONLY for level metering (`window._recLevelIv` interval, 120ms, time-domain peak).
   - Started directly from `tutSpeak()` when `window._useAudioFallback` is set (set permanently after the first SpeechRecognition `no-speech` failure on this machine; cleared only when the user picks a mic via `selectMicDevice`). SpeechRecognition takes ~6-8s to error on this machine, so the fallback flag skips it entirely.
   - **Auto-stop on silence** (added v52): the level interval tracks last-sound time (`_recLastSound`); after 1.6s of silence, ≥2s after start (`_recStartedAt`), it auto-stops the recorder by calling `startAudioRecording` again. The 10s safety auto-stop timer also remains. So hands-free turns: AI speaks → auto-listens → user speaks → auto-stops on pause → sends.
   - `mediaRecorder.onstop` gate: if peak < 0.05 → treated as silent (bytes are NOT a reliable silence check — AAC encodes silence as data too); skips Gemini, offers `autoDetectMic()` sweep (level-based) and auto-switches `mic_device_id`. Real speech → `sendAudioToGemini(base64, 3, mime)`.
   - Note: only the OLD pitch-track visualizer still uses the Web Audio gain graph (in the SpeechRecognition `onstart`), which is fine — it's audio-out only.
2. **Transcription** — `sendAudioToGemini` ~L15055 posts `{contents:[{inlineData...}], systemInstruction:"Transcribe the speech...", sourceLang}` to `POST /api/chat`. **Server now returns the raw Whisper transcript directly** — do NOT run it through an LLM "transcribe" step; that previously hallucinated replies and 503s. **Accuracy (v99): forced-zh audio goes to `whisper-large-v3`** (full model, NOT turbo — turbo misheard 我喜欢喝可乐 as 我崇拜我的心颜色) with a Chinese-only prompt biased toward lesson vocabulary (你好/喜欢/喝/可乐/咖啡...); non-zh keeps turbo for speed, turbo is the error fallback, and the no-CJK zh-retry also uses v3. In Live AI mode the transcript is sent straight to `sendToGemini` (~L17301) with no confirm UI (v100 removed the temporary ✓/✕ auto-confirm row the user asked for; v81 behavior). Study mode shows the ✓/✕ confirm that auto-confirms after 2s (`confirmTranscript`).

### Live AI conversation (the "tutor chat")
- `sendToGemini(userText)` builds `systemInstruction` from level selectors (~L17333): `never`/`beginner`/`intermediate`/`advanced`, plus `baseRules` (translator + language rules, includes anti-repetition rules 8-10: never reuse phrases from chat history, vary openings, follow topic-change requests).
- v51 anti-repetition fix: each level's TEACHING STYLE strictly limits the "drill template" (phrase → pinyin → "You can say: ...") to the FIRST message only; from message 2 it must be a natural conversational reply to what the student actually said, teach ONE new phrase, never repeat, always end with a question.
- Reply display parsing (~L17398-17463) splits the model text into Chinese runs (`cleanReply`) and tutor-language runs (`englishTranslation`). If the reply has Chinese but the model omitted the translation, v52 added a fallback: `translateToEnglish(cleanReply)` fills it into the bot bubble (`botTr-<id>`) and the side panel (`#tutWm`).
- After a bot reply in live mode, an auto-listen loop (~L17484) waits for TTS to finish (`isTtsPlaying()`) then calls `tutSpeak()` again → hands-free loop.
- **v70 self-echo fix**: `isTtsPlaying()` MUST block the mic for the FULL duration of boosted playback. In the Web Audio path (`tryPlayBoosted`, ~L14832) `s.start()` happens asynchronously after `decodeAudioData()` resolves; in v69 `_apiTtsActive` was only set after that, so on the common cached-data:URL path `isTtsPlaying()` returned false across the decode/schedule window → the auto-listen opened the mic into the tutor's just-starting reply → transcribed the tutor → feedback loop = "AI only repeats what I say". Fix: set `_apiTtsPending = true; _apiTtsActive = true;` synchronously at the top of `tryPlayBoosted` and clear `_apiTtsPending` in `s.onended`. The auto-listen settle after TTS stops is `900`ms. Keep `_apiTtsPending` cleared on EVERY exit (onended + catch) or the mic never reopens.
- The whole `geminiHistory` array is sent as `contents` each turn; reset on new session (~L17629/18109/18413).
- **Phantom-turn / hallucination defense (v97)**: prod once showed the tutor "typing without me speaking" (a fake "Thank you." turn) and misreading spoken Chinese as English. Three-layer fix, don't regress: (1) client onstop gate in `startAudioRecording` now rejects clips with `peak < 0.05` OR `window._recSoundMs < 200` (sustained-voiced-ms tracked by the 120ms level interval; clicks/breaths/gulps can't satisfy it) — silence never reaches Whisper; (2) audio `sourceLang` payload is now `getSpeechSrcLang() || 'zh'`, so mic lang `auto` forces Chinese instead of Whisper auto-detecting (which turned Mandarin into Latin gibberish/English); (3) server `/api/chat` drops no-CJK transcripts made of ≤2 filler words (`thank|thanks|you|the|subtitles|watching|speaker|...`) as 400 no-speech — these survive both the raw zh-retry (isEnglish is true) and the echo filter, so they used to reach the tutor as a fake user turn. Real 1-word answers like yes/no/ok/good are NOT in the drop set. v96 bundled: `never` level = hard HSK 1 whitelist (~60 words) + ≤7-char single sentence + grammar lock; `beginner` = HSK 1-2 whitelist + banned list (把/被/虽然...但是/如果...就/越...越/已经/曾经/idioms) + ≤2 sentences each ≤10 chars.
- **Full translation coverage (v53)**: tutor content translates to the user's selected language via `t()` using `OFFLINE_DICTIONARY` (large per-language dicts: es/fr/ja/ko/de/pt/it/ru/vi). For strings MISSING from the dictionary, `ensureTutorTranslation(text, els)` (~L17262) AI-translates on the fly into `getTutorLangName()` via `POST /api/chat` and caches in localStorage key `tutor_ai_tr_cache`. Wired into `advanceTutor` (side panel `#tutWm`/`#tutTip` + bot bubble) and `coachPronunciation` (meaning/tip spans). Live-mode replies are already translated by the model (`langName` in systemInstruction) with the `translateToEnglish` fallback.

## TTS voices (server /api/tts, v87)
- **Robotic-voice fix (v87)**: `/api/tts` GET+POST no longer default to the robotic Google `translate_tts?client=gtx` for non-Chinese. New order: **Edge TTS (Microsoft neural voices)** → Fish (zh only, when `FISH_AUDIO_KEY` set or `engine=fish`) → gtx last-resort. `engine=google` still forces gtx directly.
- Edge TTS is implemented lean in `server.js` (requires `ws`, NOT the `msedge-tts` npm pkg — that one has `preinstall: npx only-allow pnpm` which **breaks Railway npm install**): `edgeTts()` ~L84 builds `edgeWssUrl()` (Sec-MS-GEC = SHA-256 hex of `${windowsTicks(300s-rounded)}${EDGE_TRUSTED_CLIENT_TOKEN}`), opens `wss://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1` with the Edge UA + `chrome-extension://jdiccldimpdaibmpdkjnbmckianbfold` Origin, sends `speech.config` then `Path:ssml` frames; collects `Path:audio` binary frames until `Path:turn.end` (25s timeout; error/close reject).
- Voice map `edgeVoiceForLang()` (~L47) covers en/es/fr/ja/ko/de/pt/it/ru/vi/th/id/ar/tr + zh-TW/zh-HK; unknown → `en-US-AriaNeural`. Output `audio-24khz-96kbitrate-mono-mp3`; rate = 0.5–2.0 passed straight to the `<prosody rate>` multiplier. Text is `escapeXml`'d, capped 500 chars.
- **Double-voice guard (v88)**: overlapping speak requests used to start TWO WebAudio BufferSources (or an audio element over a boosted source) → the same phrase heard twice. `speakViaAPI` (~L14951) captures a play-generation token (`_ttsPlayToken`, bumped by every `stopApiTts()`); `tryPlayBoosted(~L14890)` aborts its async decode/schedule if the token moved, and stops any previous buffer source before starting; `playViaAudio` and the fetch `.catch` (fallback TTS) are gated on the token too. Result: at most ONE voice ever plays, all languages. Don't regress the token checks when touching these functions.
- **Organic tone-curve visualizer (v89)**: the bottom `.tone-curve-wrap` analyzer (cyan target / green student / gold AI lines) no longer draws robotic straight `L` pitch polylines. `curvePathFromPoints(pts)` (~L19958) renders Catmull-Rom→Bézier smooth curves, `filteredPitch()` (~L19974) is a 5-sample median low-pass on live autocorrelated pitch (both `startTutorPitchTrack` tick ~L20095 and `startTutorAiVisualizer` tick ~L20177 use them), and `ensureToneCurveGradients(svg)` (~L19992) injects `#studentGrad`/`#aiGrad` linearGradients (transparent-left → solid-right oscilloscope fade) that CSS references as `stroke: url(#...)`. Student curve is now solid (dasharray removed) with round joins; `curvePulse` keyframes are opacity-only (stroke-width strobing removed). Keep the gradients in CSS in sync with `ensureToneCurveGradients`.
